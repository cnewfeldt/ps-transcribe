# 18.1-09 — D-20 lastError auto-clear (UAT issue #3)

## What was done

Closed the one-way error trap from UAT test 9: after D-20 fired (user clicks
Meeting/Memo with zero destinations), `transcriptionEngine.lastError`
persisted indefinitely. Enabling a destination in Settings did not clear it,
so `hasError == true` kept the start buttons inert until app restart.

**Fix:** centralize the D-20 message as a single named constant; observe
`saveDestinations.isAnyDestinationEnabled` in ContentView's modifier stack
and exact-match-clear `lastError` only when it equals that constant.

## Producer-side diff

```swift
// before
guard saveDestinations.isAnyDestinationEnabled else {
    transcriptionEngine?.lastError =
        "No save destination configured. Enable Local File, Obsidian, or Notion in Settings."
    return
}

// after
guard saveDestinations.isAnyDestinationEnabled else {
    transcriptionEngine?.lastError = DestinationGuardErrors.noDestinationsConfigured
    return
}
```

## New onChange handler in ContentView body

```swift
.onChange(of: saveDestinations.isAnyDestinationEnabled) { _, isEnabled in
    guard isEnabled,
          transcriptionEngine?.lastError == DestinationGuardErrors.noDestinationsConfigured
    else { return }
    transcriptionEngine?.lastError = nil
}
```

Exact-match `==`, not `hasPrefix` / `contains`. Mic-permission, save, and
model-download errors flow through the same `lastError` slot but never
match the D-20 constant, so they are preserved.
