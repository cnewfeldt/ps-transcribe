| Option | Description | Selected |
|---|---|---|
| Yes -- dictation goes to Notion when enabled (Recommended) | Per "dictation is just content," Notion is one of the destinations. | ✓ |
| No -- Notion is meeting/voice-memo only | Each destination declares which content types it accepts. | |

**User's choice:** Yes -- uniform fan-out.
**Notes:** Empty / default values populate properties dictation lacks. Confirmed on a follow-up question that Notion writes will use a session-type property to differentiate content types in the single database.

## Obsidian section shape (revisited)

**Question (initial):** After Local File takes over folder pickers, what does `Section("Obsidian")` become?

| Option | Description | Selected |
|---|---|---|
| Vault-detection overlay on Local File (Recommended) | Section shows status + deep-link toggle; no folder pickers. | |
| Standalone destination with its own paths | Keeps three-folder shape (Meetings + Voice memos + new Dictation). | |
| Remove Section("Obsidian") entirely | Vault detection happens transparently in the library row. | |

**User's choice:** Free-text response: *"I would like to review the obsidian folder save location. I think we should follow the same idea as notion; one save point (in this case a folder location in an obsidian vault). This save point would then place all the saved files in them, and those would have a property in it called 'session-type'. So I would like to move to one folder save area for obsidian and follwo the same property entry type as notion."*

**Notes:** User chose a fourth option not in the original list -- **single folder + YAML frontmatter `session-type` property**. Mirrors Notion's pattern in Obsidian's native idiom. This collapsed the previous "three folder pickers for Obsidian" plan into a single folder + frontmatter-tagged files. Architecturally symmetric with Notion (single DB + property) and Local File (single root + subfolder).

## Dictation file format policy

**Question:** Today `DictationLogger` writes plain markdown (no YAML frontmatter, per Phase 16 D-01). After the refactor, what's the format policy for dictation files?

| Option | Description | Selected |
|---|---|---|
| Per-destination format (Recommended) | Local File Dictation/: plain markdown (subfolder tags it). Obsidian: YAML frontmatter with session-type. Notion: DB property. | ✓ |
| Frontmatter everywhere | Dictation always has YAML frontmatter, regardless of destination. | |
| Plain everywhere, no Obsidian frontmatter | Dictation stays plain markdown in all destinations; Obsidian uses filename or subfolder convention. | |

**User's choice:** Per-destination format.
**Notes:** Each destination uses its native idiom for content-type expression. Phase 16 D-01 (plain markdown for dictation) is preserved for the Local File path; Obsidian gains frontmatter on dictation files since `session-type:` is its tagging mechanism.
