# Requirements: PS Transcribe v1.2

**Defined:** 2026-04-27
**Milestone:** v1.2 -- Standalone Dictation + Model Auto-Update + Dark Mode Parity
**Core Value:** Users can record meetings and voice memos with accurate, private, on-device transcription. All processing stays on-device.

**Milestone goal:** Make PS Transcribe useful as a standalone dictation tool -- hotkey-triggered capture that writes to clipboard and/or a plain OS folder with no Obsidian/Notion required -- let the ASR model update without shipping a new app build, and bring the macOS app to full dark-mode parity so every surface respects the system appearance.

## v1.2 Requirements

Requirements for this milestone. Each maps to roadmap phases (mapping populated by `/gsd-plan-phase`).

### Dictation -- Hotkey + Clipboard

- [x] **DICT-01**: User can trigger dictation from any app via a configurable global hotkey (default `Cmd+Shift+D`)
- [x] **DICT-02**: User can choose between toggle and press-and-hold hotkey modes (default: toggle)
- [x] **DICT-03**: User sees a menu bar indicator while dictation is recording
- [x] **DICT-04**: User sees a floating HUD with live partial transcription during dictation
- [x] **DICT-05**: On dictation stop, final transcript text is written to the system clipboard
- [~] **DICT-06**: ~~Previous clipboard contents are restored after a configurable delay (default 3s)~~ -- RETIRED 2026-05-11 in Phase 26-02 after UAT discovered the restore broke the dictation->paste user flow. Privacy markers (TransientType + AutoGeneratedType) remain on every clipboard write so managers still skip the entry.
- [x] **DICT-07**: Each dictation session is saved to the existing session library
- [x] **DICT-08**: User can cancel dictation with Escape (or second hotkey tap) with no clipboard write; sessions over 30s prompt for confirmation
- [x] **DICT-09**: Clipboard write includes pasteboard markers (`org.nspasteboard.TransientType` + `AutoGeneratedType`) so dictation text is excluded from clipboard-history apps (Alfred, Maccy, Pasta)
- [x] **DICT-10**: Floating HUD respects existing privacy mode (`NSWindowSharingType.none`) -- `DictationWindowController.swift:47`
- [x] **DICT-11**: Only one recording session can be active at a time (dictation and meeting recording are mutually exclusive)

### Dictation -- Plain-Folder Output

- [x] **FOLDER-01**: User can configure a plain OS folder as a dictation output destination via a folder picker in Settings
- [x] **FOLDER-02**: Dictation transcripts written to the plain folder are clean markdown with no YAML frontmatter
- [x] **FOLDER-03**: Plain-folder filenames follow a human-readable date convention (e.g., `2026-04-27 14-32 Dictation.md`) and avoid collisions for sessions seconds apart
- [x] **FOLDER-04**: User can choose dictation output mode: clipboard only, plain folder only, or both
- [x] **FOLDER-05**: Plain-folder path persists across app restarts (UserDefaults)

### Model Auto-Update

- [x] **MODEL-01**: App checks for newer FluidAudio ASR model versions in the background, no more than once per 24 hours
- [x] **MODEL-02**: When an update is available, a non-intrusive badge appears in Settings > Model (no modal alerts, no notifications)
- [x] **MODEL-03**: User explicitly initiates the model download (no silent auto-install)
- [x] **MODEL-04**: Model download shows progress and is cancellable -- inline progress row in Settings > Speech Model (D-09 supersedes "reuse v1.0 Phase 4 onboarding sheet" wording)
- [x] **MODEL-05**: Downloaded model version persisted so checks are not repeated unnecessarily
- [x] **MODEL-06**: Failed or partial downloads do not corrupt the active model (staging download, SHA-256 verify, atomic rename swap)
- [x] **MODEL-07**: Model swap deferred when a recording or dictation session is active; pending update applies after the next session ends
- [x] **MODEL-08**: Settings shows installed model version vs available version
- [x] **MODEL-09**: Manifest carries `min_app_version` so a newer model requiring a newer FluidAudio SDK is not applied until a Sparkle app update lands
- [x] **MODEL-10**: Disk-space preflight before download (skip / warn if insufficient free space)

## Out of Scope

Explicitly excluded. Documented to prevent scope creep, grounded in research and prior scope decisions.

| Feature | Reason |
|---------|--------|
| Cloud ASR fallback ("use OpenAI Whisper API when on-device is slow") | Violates the on-device privacy proposition; adds API key management, network dependency, cost. |
| LLM cleanup / reformatting of dictated text | LLM analysis was removed in the 2026-04-04 scope reduction (archived at `archive/llm-analysis-attempt`); raw transcripts only. |
| Auto-paste directly into the focused field via accessibility APIs | Fragile in password fields, sandboxed apps, and remote desktops; requires broader permissions. Clipboard-only is universally compatible. |
| Silent background model installation | Models are large; surprise downloads hostile on metered connections. User-initiated only. |
| Dictation history search | Out of scope for v1.2; session library covers basic history. |
| Watch folder for input audio files | Different use case (file transcription vs live dictation). |
| Telemetry / usage analytics | Hard project constraint: no telemetry, ever. |
| Model rollback UI for pinning older ASR versions | Low demand, high complexity; users can simply not tap "Update." |
| ScreenCaptureKit privacy guarantee for the HUD | Documented macOS limitation -- ScreenCaptureKit captures composited displays regardless of `NSWindowSharingType`. Will be documented, not engineered around. |
