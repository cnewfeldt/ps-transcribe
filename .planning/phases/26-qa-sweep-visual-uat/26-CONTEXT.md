## Implementation Decisions

### Test environment readiness

- **D-01:** **Hybrid environment with documented gaps.**
  - **QA-01 / QA-02 (clipboard exclusion under Maccy + Alfred):** User has one of the two installed; the other is installed temporarily for the QA cycle (Maccy via Homebrew is free; Alfred Powerpack is required for clipboard history if Alfred is the missing one). Both run live during dictation sessions to verify `org.nspasteboard.TransientType` + `AutoGeneratedType` markers exclude the transcript. Mark UNTESTABLE-this-cycle (option D) was rejected — the live test is the only meaningful coverage and the install cost is small.
  - **QA-03 (multi-monitor HUD positioning):** **Single-display only.** User does not have a multi-monitor rig. The 4-config matrix (primary, secondary-left, secondary-right, vertical orientation) plus mid-recording disconnect is split: the single-display position case runs as a normal PASS row; the multi-monitor sub-scenarios are recorded in 26-UAT.md as UNTESTABLE-this-cycle with a gap note pointing at `DictationWindowController.swift` (`NSScreen.screens` positioning math) for a future hardware-available cycle. Sidecar / iPad as second display (option B) was rejected — adds latency and a confounding factor that muddies any FAIL signal. Synthesized `NSScreen` mock test (option D) was rejected — turns QA-03 into a code phase, conflicts with the manual-sweep boundary of this phase.
  - **QA-04 (security-scoped bookmark survival):** **Entire scenario WITHDRAWN.** Codebase verification (entitlements file inspection + AppSettings.swift / SaveDestinations.swift grep) confirmed PS Transcribe is **not sandboxed** — `PSTranscribe.entitlements` contains only `com.apple.security.device.audio-input` and `com.apple.security.device.screen-capture`; no `com.apple.security.app-sandbox` key. `localFileRoot` and `obsidianFolderPath` persist as raw `String` paths in `UserDefaults` (`AppSettings.swift:82,97`), not as `bookmarkData(options: .withSecurityScope)`. There is no `startAccessing` / `stopAccessing` call in `PSTranscribe/Sources` (verified via grep, zero hits). The QA-04 premise from `research/PITFALLS.md` line 519 was speculative about a sandboxed scenario that did not materialize; UserDefaults string-path persistence is guaranteed by Apple's `UserDefaults` contract and survives both relaunch and reboot trivially. App-relaunch half only (option B) was rejected — testing a non-existent bookmark layer produces no signal. Reboot test (option A) was rejected for the same reason plus the disruption cost.

### Failure routing protocol

- **D-02:** **Batch-triage after full sweep, size-based routing.** Run all 9 scenarios first, log PASS / FAIL only in 26-UAT.md without making fix decisions inline. After the sweep completes, read FAILs as a group and route by size:
  - **In-phase plan (`26-NN-PLAN.md`):** fix is < 1 hour AND touches ≤ 2 files (e.g., HUD origin offset, missing privacy marker, off-by-one threshold). Phase 26 ships only after all in-phase fixes pass a re-run of their scenario.
  - **Deferred todo (`.planning/todos/pending/`):** anything bigger or architectural (e.g., new sandboxing model, refactor of HUD positioning system, new permission flow). Todo title prefix matches the QA-NN that surfaced it for traceability.
  - Inline triage (option B) was rejected — risks scope creep; a FAIL might look fixable until a related FAIL elsewhere reframes it. Doc-only sweep (option C) was rejected — small fixes are cheap to ship in-phase and align with `gsd-cleanup` cadence. "Always plan, never todo" (option A) was rejected — would force architectural FAILs into Phase 26 and inflate the phase indefinitely.

### Build provenance + evidence weight

- **D-03:** **Local debug build from `main` HEAD; text attestation only; QA-06..QA-09 cite Phase 21.**
  - **Build:** `swift build -c debug` (or Xcode Run) from current `main`. Matches the Phase 24 `24-HUMAN-UAT.md` and Phase 21 `21-HUMAN-UAT.md` precedent. Notarized Sparkle release v2.2.0 (option C) was rejected — stale relative to Phase 25 commits and the QA-FUT-01 backlog targets v1.3 polish, not retroactive validation of v2.2.0 specifically. Both-build cross-check (option D) was rejected — doubles execution time without proportional signal given the scenarios are mostly clipboard / window / disk semantics that don't depend on optimization mode or notarization.
  - **Evidence:** Text attestation only (`expected:` / `result:` lines, status). Phase 24 + Phase 21 set this precedent; Phase 23 owns visual baselines via `swift-snapshot-testing`, and they are the right surface for visual evidence — QA scenarios in this phase are behavioral. Screenshots for QA-06..QA-09 (option B) was rejected because of D-03b (citation, not re-execution). Screen recording for the full sweep (option D) was rejected — large artifact, awkward to review, low ROI for behavioral PASS / FAIL.
  - **QA-06..QA-09 (titlebar visual UAT):** **Citation rows, not fresh execution.** `21-HUMAN-UAT.md` already records all 4 scenarios as PASS via user attestation 2026-05-01 (`status: resolved`). Phase 25 D-03 cross-references Phase 26 to satisfy the visual half of REQ-21.5 / REQ-21.2b / REQ-21.3b — that contract is honored by the rows existing in 26-UAT.md. Each row in 26-UAT.md will read: `Source: 21-HUMAN-UAT.md (passed 2026-05-01, user attestation)` plus a one-line summary of the scenario expectation. Fresh re-execution (option A) was rejected — code path between 21-HUMAN-UAT.md commit and `main` HEAD has had no titlebar changes (verified during 25-CONTEXT analysis: only Phase 25 test additions touched `AppearancePreference`, not Chronicle bridge). Smoke-test re-flip (option B) was rejected — half-fidelity coverage that neither honors the prior pass nor provides new signal. Skip without citation rows (option C) was rejected — would leave 26-UAT.md without the QA-06..09 rows that Phase 25 D-03 explicitly relies on.

### Misc — CI todo, artifact name, plan structure

- **D-04:**
  - **CI infrastructure todo deferred and explicitly noted.** `ci-build-check-failing-on-main.md` (Swift 6 strict-concurrency at `TranscriptionEngine.swift:238,342` from commit `2a2e7af6` + missing Xcode 26 on macos-26 runner) was matched at score 0.6 by `gsd-sdk query todo.match-phase 26` but is **not folded** into Phase 26 scope. Folding (option B) was rejected — broadens "QA Sweep" beyond the PITFALLS-origin checklist and would gate the phase on unrelated Swift 6 work. Cross-ref recorded here (option C) so a future reader sees the todo was considered and intentionally excluded; the existing todo file is the canonical tracker.
  - **Artifact filename:** **`26-UAT.md`** (matches ROADMAP success criterion 1 and the `18.1-UAT.md` precedent). The `*-HUMAN-UAT.md` convention from Phase 24 / 21 / 17 (option B) was rejected because ROADMAP wording wins over per-phase convention drift — and a frontmatter / structure read of `18.1-UAT.md` shows it is the closest precedent for a multi-scenario manual-execution artifact (vs. `24-HUMAN-UAT.md` which is a single CI-confirmation row).
  - **Plan structure:** **Single execution plan `26-01-PLAN.md`** covers the entire 9-scenario sweep plus 26-UAT.md authoring as one atomic unit. Conditional fix plans `26-02-PLAN.md`, `26-03-PLAN.md`, … are appended **only if** batch-triage (per D-02) routes one or more FAILs to in-phase remediation. Two-plan prep / execute split (option B) was rejected — prep is mostly a checklist (install missing clipboard manager, build app, draft 26-UAT.md skeleton) that does not warrant its own plan boundary. Per-scenario plans 26-01..26-09 (option C) was rejected — absurdly granular for a 9-item human-driven sweep that is one continuous session.

### Claude's Discretion

- **`26-UAT.md` frontmatter and row schema** — Use `18.1-UAT.md` as the closest precedent (multi-scenario manual UAT artifact). Frontmatter keys: `status` (initial value `in-progress`, transitions to `resolved` / `approved-with-debt`), `phase: 26-qa-sweep-visual-uat`, `source: [REQUIREMENTS.md, ROADMAP.md]`, `started: <ISO timestamp>`, `updated: <ISO timestamp>`, `resolved: <ISO timestamp>`. Per-scenario row shape: heading `### N. QA-NN — <short description>`, `expected:` line, `result:` line, optional `notes:` block for FAIL context (logs / Console.app excerpts) or routing decision (in-phase plan ID or todo filename). Final `## Summary` block with counts (`total`, `passed`, `failed`, `withdrawn`, `untestable-this-cycle`). Planner picks final exact wording within this skeleton.
- **Order of scenarios in 26-UAT.md** — Default to QA-NN numerical order. Planner can group by surface (clipboard cluster QA-01/02 → window cluster QA-03 → persistence QA-04 → preflight QA-05 → titlebar cluster QA-06..09) if it produces a smoother human execution flow, but numerical order is the bias.
- **Maccy or Alfred — which one is the regular driver, which gets installed temporarily** — User has one already (D-01); planner asks at execution start which one is missing and adds the install step (`brew install --cask maccy` or Alfred direct download) as the first step of `26-01-PLAN.md`. Cleanup (uninstall after sweep) is at user's discretion — note the temporary install in 26-UAT.md so it is not forgotten.
- **QA-03 single-display PASS criteria** — Bias: HUD appears at the documented bottom-of-primary-screen position when dictation is triggered, does not clip, and respects safe-area insets (notch / Dock). Planner picks the exact pass criterion language; reuse `21-HUMAN-UAT.md` row format as the template.
- **QA-05 disk-space preflight test mechanics** — Bias: lower the `MIN_FREE_BYTES_FOR_MODEL_UPDATE` threshold (or equivalent) in `ModelUpdateService.swift` via a debug-only build flag, trigger an update check, confirm the warning surfaces with a dismissible alert and the update is deferred. Real-disk-fill (option A) is the gold standard but disruptive and slow; debug-build threshold lowering produces equivalent code-path coverage with zero disruption. Planner picks the exact mechanism inside `26-01-PLAN.md` and reverts the flag before commit. Untestable mark (option D from PITFALLS-style framing) is the fallback if the threshold is not parameterized — planner must read `ModelUpdateService.swift` to confirm before locking the mechanism.
- **Routing-decision recording in 26-UAT.md** — Bias: each FAIL row gets a `routing:` field with value `in-phase: 26-NN-PLAN.md` or `todo: <filename>.md`. Planner picks exact field shape; consistent with the `notes:` convention from `18.1-UAT.md`.
- **`26-UAT.md` trailing summary footer** — Include a `## Cross-References` section listing the canonical sources used (REQUIREMENTS.md QA-01..QA-09 IDs, 21-HUMAN-UAT.md for QA-06..09 citation, PITFALLS.md "Looks Done But Isn't" for QA-01..05 origin, 25-CONTEXT.md D-03 for the QA-06..09 contract). Planner picks exact wording.

## Specific Ideas

- **QA-04's WITHDRAW reason must be the codebase-verified one, not the speculative one.** The PITFALLS.md framing of "security-scoped bookmark survival" was speculative about a sandboxed scenario that did not materialize. The accurate reason is: app is non-sandboxed (entitlements verified), folder URLs persist as plain `String` paths in `UserDefaults` (`AppSettings.swift:82,97`), no `bookmarkData(options: .withSecurityScope)` calls and no `startAccessing` / `stopAccessing` anywhere in `PSTranscribe/Sources` (verified via grep, zero hits). Future readers should not be left with a "trust Apple's API" shorthand — the reason is "the API isn't in use here."
- **Maccy + Alfred privacy-marker semantics** — both clipboard managers honor `org.nspasteboard.TransientType` and `AutoGeneratedType` per the `nspasteboard.org` informal contract. The PASS criterion is **absence** in the manager's history UI, not a positive event log. QA-01 / QA-02 PASS rows must record the manager version and the relevant settings (e.g., Maccy's "Ignore Items" toggle state).
- **QA-06..QA-09 citation row format** — each row reads: scenario one-liner from `21-HUMAN-UAT.md` Tests 1–4, then `Source: .planning/milestones/v1.2-phases/21-appearance-override/21-HUMAN-UAT.md (Test N, passed 2026-05-01, user attestation)`. Date and attestation pattern match the WITHDRAWN-row precedent from Phase 24/25.
- **Phase 26 status terminal state** — likely `approved-with-debt` because QA-03 multi-monitor sub-scenarios will be UNTESTABLE-this-cycle; planner should not block on `resolved` if every other scenario is PASS / WITHDRAWN.
