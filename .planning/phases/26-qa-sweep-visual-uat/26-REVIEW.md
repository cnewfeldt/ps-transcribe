## Warnings

### WR-01: Stale UserDefaults key `clipboardRestoreDelay` not cleaned up on upgrade

**File:** `PSTranscribe/Sources/PSTranscribe/Settings/AppSettings.swift` (no longer references the key)
**Issue:** Users who launched a prior build of v1.2 will have a `clipboardRestoreDelay` Double persisted in `UserDefaults.standard`. After this phase ships, nothing reads or removes that key, so it lingers in `~/Library/Preferences/<bundle>.plist` indefinitely. This is not a correctness bug today, but:
1. It violates the stated v1.2 D-17 "rip-and-replace" posture (no migrations because not yet released to users) — if any external user did install a pre-26 build, they carry forward an orphan key.
2. If a future v1.3 feature reuses the same key name with different semantics (e.g. an `Int` for some unrelated delay), `UserDefaults.standard.double(forKey:)` will silently return the old user's stored Double cast — type-mismatch bugs are notoriously hard to trace.

**Fix:** Either (a) accept this and document in `26-02-SUMMARY.md` that orphan key cleanup is deferred to v1.3, or (b) add a one-shot migration in `AppSettings.init()`:
```swift
// Phase 26-02: DICT-06 retired -- remove orphaned key from prior builds.
defaults.removeObject(forKey: "clipboardRestoreDelay")
```
Option (a) is consistent with D-17. If chosen, capture this as a `todos/pending/` item so v1.3 doesn't accidentally collide on the key name.

### WR-02: `_test_writeToClipboard` debug surface widened relative to test coverage

**File:** `PSTranscribe/Sources/PSTranscribe/App/DictationCoordinator.swift:443-445`
**Issue:** The `#if DEBUG` block retains `_test_writeToClipboard(_:)` after `_test_scheduleClipboardRestore(_:)` was removed. This is fine on its own, but the function is now the only `_test_*` clipboard-related shim, and `ClipboardPrivacyMarkersTests.swift` is its sole caller. With DICT-06 gone, the production path that exercises `writeToClipboardWithPrivacyMarkers` is reachable only via `endDictation()` (line 236). If a future refactor inlines or renames `writeToClipboardWithPrivacyMarkers`, the test shim remains as dead infrastructure pointing at a deleted helper.
**Fix:** No code change required, but consider folding the test surface into a single `_test_writePrivacyMarkers(_:)` named after what it actually verifies, or add a comment:
```swift
#if DEBUG
/// Sole consumer: ClipboardPrivacyMarkersTests. Exposes the private
/// privacy-markers helper so the test can assert pasteboard state without
/// running the full endDictation pipeline. If you rename
/// writeToClipboardWithPrivacyMarkers, update both this shim and its 3 callers.
func _test_writeToClipboard(_ text: String) {
    writeToClipboardWithPrivacyMarkers(text)
}
#endif
```
