## What changed

Retired DICT-06 (post-dictation clipboard restore). Removed:

- `scheduleClipboardRestore(after:)` and the `restoreTask`, `savedPasteboardItems`, `postWriteChangeCount` machinery in `DictationCoordinator.swift` (-49 lines)
- `clipboardRestoreDelay` property + UserDefaults init in `AppSettings.swift` (-13 lines)
- "Restore previous clipboard after" Stepper from `SettingsView.swift` (-15/+1 — adjusted trailing description text)
- `Phase18/ClipboardRestoreTests.swift` entirely (deleted)
- `clipboardRestoreDelay` references from `AppSettingsTests.swift`, `SnapshotFixtures.swift`, and `Phase18.1/SettingsView18_1Tests.swift` (-93 lines total)
- DICT-06 status updated in `.planning/milestones/v1.2-REQUIREMENTS.md` from `Complete` to `Retired (Phase 26-02)` with a one-line retirement note

The clipboard write path is now: `clearContents()` → `setString(text)` → set `org.nspasteboard.TransientType` + `AutoGeneratedType` privacy markers. No restore, no snapshot, no changeCount guard.

## Why

26-01 Task 2 smoke test (UAT) discovered the 3-second restore was breaking the user's mental model. Cary (project owner) reasoned: "why the restore, just write to the clipboard like the user 'copied' text in to it." Approved Option A from the design discussion: delete entirely.

The DICT-06 design (added in Phase 18 to mitigate Pitfall #6, the "user copies something else mid-window" race) sounded reasonable on paper and passed unit tests in isolation, but the integration UX was wrong: dictation IS a copy operation, and a 3-second restore window is shorter than the typical "switch app, click into field, paste" flow. Privacy markers (DICT-09) remain on every clipboard write so Maccy/Alfred/Pasta still skip the entry — the only thing lost is the auto-restore.
