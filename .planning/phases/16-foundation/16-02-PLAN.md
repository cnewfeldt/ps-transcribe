**Important constraint:** AppSettings reads/writes `UserDefaults.standard`, which is a process-global side effect. Tests must NOT pollute the developer's real UserDefaults or interfere with other tests. The test suite must isolate state.

Two viable isolation strategies (use Strategy A, simpler):

**Strategy A (chosen): Save / restore real UserDefaults around each test, using a known set of keys.**

The test sets each key via `UserDefaults.standard`, instantiates `AppSettings()`, asserts behavior, then `removeObject(forKey:)` for each touched key in a `defer`. This works because Phase 16 has no nested AppSettings or background writers running during tests.

**Strategy B (rejected): swap in a custom UserDefaults via `UserDefaults(suiteName:)`.** Requires changing `AppSettings.init()` to accept an injected `UserDefaults` parameter, which is out of scope for Phase 16 (per D-13 / "build only what's requested"). Defer to a future test-architecture pass.
