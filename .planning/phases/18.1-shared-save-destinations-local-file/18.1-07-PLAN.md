<objective>
Fix Phase 18.1 UAT issue #1: the NSOpenPanel opened by the Obsidian and Local File folder pickers shows its descriptive text in a low-contrast accessory slot rather than the high-contrast title bar. The user reads the (unset) default system title and reports it as "barely legible."

Root cause (diagnosed in `.planning/debug/18.1-uat-issue-1-choose-folder-ui.md`): the `chooseFolder(message:onSelect:)` helper at `SettingsView.swift:647-657` sets only `panel.message`, leaving `panel.title` and `panel.prompt` as system defaults. Both the Obsidian and Local File pickers route through this single helper.

Fix: promote the message string to `panel.title` (high-contrast title bar) and set `panel.prompt = "Choose"` (overrides the system default "Open" action button to match the in-app verb). Keep `panel.message` so the descriptive text still appears in the accessory slot for users who read it there. One six-line edit; both pickers benefit.

The misdiagnosed sub-symptom — "icon not rendering" on the Choose button — is **out of scope**. The button has no icon in code (it's `Button("Choose...")` plain text), and the debug session recommends a clarification round-trip with the user before treating that as a defect. This plan handles only the verified low-contrast title issue.

Purpose: restore D-15 verification path (UAT test 1) and ship a usable folder picker UX.
Output: `swift build` green; helper sets all three NSOpenPanel string slots.
</objective>
