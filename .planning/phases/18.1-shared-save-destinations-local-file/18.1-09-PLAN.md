<objective>
Fix Phase 18.1 UAT issue #3: after D-20 fires (user clicks Meeting/Memo with zero destinations enabled), the `transcriptionEngine.lastError` message persists indefinitely. The user enables a destination in Settings, returns to the main window, and the start buttons stay inert because `hasError == lastError != nil`. Only an app restart clears the trap. This is a missing observer wire, not a regression.

Root cause (diagnosed in `.planning/debug/18.1-uat-issue-3-stale-d20-error.md`):
1. `ContentView.startSession` at `ContentView.swift:826-830` sets `transcriptionEngine.lastError` to a "no destinations" string and `return`s early.
2. `CaptureDock` start buttons silently no-op when `!hasError` (CaptureDock.swift:147 / 184).
3. The only `lastError = nil` sites in the project are bound to session-start retries or permission-grant flows -- all unreachable while the buttons are inert.
4. No `.onChange(of:)` listens for a destination toggle and clears the error.
5. Result: one-way trap, requires app restart.

Fix (per debug session recommendation):

1. **Extract the D-20 message into a single named constant.** Place it in `SaveDestinations.swift` as `enum DestinationGuardErrors { static let noDestinationsConfigured = "..." }`. Both the producer (ContentView.startSession guard) and the consumer (auto-clear handler) reference the same constant. Eliminates string drift.
2. **Add an exact-match scoped auto-clear in ContentView's modifier stack.** A new `.onChange(of: saveDestinations.isAnyDestinationEnabled)` clears `transcriptionEngine.lastError` ONLY when the new value is `true` AND the current `lastError` exactly equals `DestinationGuardErrors.noDestinationsConfigured`.
3. **DO NOT broaden the button-disable predicate.** Per debug session: "Do NOT change the button-disable predicate to 'lastError nil OR isAnyDestinationEnabled' -- that would let the user click through other legitimate errors. Targeted clear is the correct discipline." The button gates stay as they are.
4. **Add a regression test** that asserts (a) auto-clear works on the D-20 message and (b) auto-clear leaves a mic-permission message untouched. Without (b), a future contributor might broaden the match and quietly mask permission errors.

Update the existing `ZeroDestinationsBlockTests` source-grep test to match the new constant reference (the test currently looks for the literal string in `ContentView.swift`; after refactor the literal lives in `SaveDestinations.swift`).

Purpose: restore destination-recovery UX so the user no longer needs to relaunch the app.
Output: `swift build` green; full `swift test` green; D-20 trap closed.
</objective>

**Step A — extract the D-20 message constant in `Services/SaveDestinations.swift`.**

At the top of `SaveDestinations.swift` (above the `final class SaveDestinations` declaration), add a small enum-as-namespace:

```swift
/// User-facing error messages produced by destination-state guards.
///
/// Centralized so producers (ContentView.startSession D-20 guard) and consumers
/// (.onChange auto-clear in ContentView) reference a single source of truth and
```

**Step C — add the scoped auto-clear in ContentView's body modifier stack.**

Find the existing `.onChange(of: settings.inputDeviceID)` block at line 432 and add a sibling immediately after it (matching the established convention):

```swift
.onChange(of: settings.inputDeviceID) {
    if isRunning {
        transcriptionEngine?.restartMic(inputDeviceID: settings.inputDeviceID)
    }
}
.onChange(of: saveDestinations.isAnyDestinationEnabled) { _, isEnabled in
    // 18.1 gap-09 (UAT issue #3): when the user enables a destination after
    // the D-20 guard fired, clear the inline error so the start buttons
    // re-engage. Scope is exact-match against the D-20 constant -- mic
    // permission, save failures, and model download failures must NOT be
    // cleared by this path. See .planning/debug/18.1-uat-issue-3-stale-d20-error.md.
    guard isEnabled,
          transcriptionEngine?.lastError == DestinationGuardErrors.noDestinationsConfigured
    else { return }
    transcriptionEngine?.lastError = nil
}
```

Critical:
- `==` exact-match, NOT `hasPrefix`, NOT `contains`. The debug session explicitly warns "must NOT broaden the predicate" because broader matches would mask unrelated errors.
- Guard checks both conditions:
  1. `isEnabled == true` -- only act on the false -> true transition (the recovery direction).
  2. `transcriptionEngine?.lastError == DestinationGuardErrors.noDestinationsConfigured` -- only the D-20 string. If `lastError` is already nil OR contains a different error, leave it alone.
- DO NOT add this clear inside `CaptureDock` button handlers, inside `TranscriptionEngine`, or inside `SaveDestinations` itself. ContentView is the right place because it owns the binding between `saveDestinations` (input source) and `transcriptionEngine` (error sink). Moving the wire elsewhere would either introduce circular dependencies or violate the existing pattern (the file already hosts six other `.onChange` modifiers for cross-domain wiring).
- DO NOT modify the button-disable predicate in `CaptureDock`. Buttons stay gated on `!hasError`.

**Step D — write the regression test at `PSTranscribe/Tests/PSTranscribeTests/Phase18.1/D20RecoveryAutoClearTests.swift`.**

Two tactical considerations:
- ContentView's `.onChange` modifier is a SwiftUI side effect; mounting ContentView in a test is heavyweight and fragile. The cleaner test path is to assert behavior that is **structurally guaranteed** by the code: (1) the constant exists, (2) the producer + consumer reference it, (3) a unit-level harness simulates the behavior of the .onChange handler against a real `SaveDestinations` + a stub TranscriptionEngine-style holder.
- Use a small in-test helper that mirrors the .onChange handler's logic exactly. This decouples the test from SwiftUI's hosting infrastructure while still exercising the load-bearing predicate.

```swift
import Foundation
import Testing
@testable import PSTranscribe

@MainActor
@Suite("Phase 18.1 gap-09 -- D-20 lastError auto-clear (UAT issue #3)")
struct D20RecoveryAutoClearTests {

    /// Mirrors the predicate inside ContentView's
    /// `.onChange(of: saveDestinations.isAnyDestinationEnabled)` block. This
    /// helper exists so the test exercises the SAME logic without mounting
    /// SwiftUI. If the production handler diverges from this predicate, the
    /// source-grep test below catches it; behavioral coverage stays here.
    private func runAutoClearHandler(isEnabled: Bool, lastError: inout String?) {
        guard isEnabled,
              lastError == DestinationGuardErrors.noDestinationsConfigured
        else { return }
        lastError = nil
    }

    @Test("D-20 message clears when destinations re-enable")
    func d20MessageClearsOnEnable() {
        var lastError: String? = DestinationGuardErrors.noDestinationsConfigured
        runAutoClearHandler(isEnabled: true, lastError: &lastError)
        #expect(lastError == nil, "D-20 recovery: lastError must be cleared when isAnyDestinationEnabled becomes true")
    }

    @Test("Mic permission error is preserved (not over-cleared)")
    func micPermissionErrorPreserved() {
        let micErr = "Microphone access denied. Enable in System Settings > Privacy > Microphone."
        var lastError: String? = micErr
        runAutoClearHandler(isEnabled: true, lastError: &lastError)
        #expect(lastError == micErr, "auto-clear must NOT match unrelated errors (regression-defense)")
    }

    @Test("Save-failure error is preserved")
    func saveFailureErrorPreserved() {
        let saveErr = "Failed to write Local File transcript: permission denied"
        var lastError: String? = saveErr
        runAutoClearHandler(isEnabled: true, lastError: &lastError)
        #expect(lastError == saveErr)
    }

    @Test("Already-nil lastError is unchanged when destinations toggle on")
    func nilErrorIsIdempotent() {
        var lastError: String? = nil
        runAutoClearHandler(isEnabled: true, lastError: &lastError)
        #expect(lastError == nil)
    }

    @Test("Disabling destinations does not act (handler only runs on enable transitions)")
    func disableTransitionIsNoOp() {
        var lastError: String? = DestinationGuardErrors.noDestinationsConfigured
        runAutoClearHandler(isEnabled: false, lastError: &lastError)
        #expect(lastError == DestinationGuardErrors.noDestinationsConfigured,
                "auto-clear gates on isEnabled == true; false transitions are no-ops")
    }

    // ─── Source-grep tests (drift defense) ───

        let url = URL(fileURLWithPath: #filePath)
            .deletingLastPathComponent()

            .appendingPathComponent("Sources/PSTranscribe/Services/SaveDestinations.swift")
        return (try? String(contentsOf: url)) ?? ""
    }

    private var contentViewSource: String {
        let url = URL(fileURLWithPath: #filePath)
            .deletingLastPathComponent()

            .deletingLastPathComponent()
            .deletingLastPathComponent()
            .appendingPathComponent("Sources/PSTranscribe/Views/ContentView.swift")
        return (try? String(contentsOf: url)) ?? ""
    }

    @Test("DestinationGuardErrors.noDestinationsConfigured exists in SaveDestinations.swift")
    func constantIsCentralized() {
        #expect(saveDestinationsSource.contains("static let noDestinationsConfigured"))
        #expect(saveDestinationsSource.contains(
            "No save destination configured. Enable Local File, Obsidian, or Notion in Settings."))
    }

    @Test("ContentView producer references the constant (not the literal)")
    func contentViewProducerUsesConstant() {
        // The D-20 guard at startSession must use the constant, not the literal.
        #expect(contentViewSource.contains("DestinationGuardErrors.noDestinationsConfigured"))
        // No remaining literal copies (avoid drift).
        let literal = "No save destination configured. Enable Local File, Obsidian, or Notion in Settings."
        #expect(!contentViewSource.contains(literal),
                "The D-20 message literal must live ONLY in SaveDestinations.swift")

    @Test("ContentView contains the auto-clear .onChange wired to isAnyDestinationEnabled")
    func contentViewHasAutoClearHandler() {
        #expect(contentViewSource.contains(".onChange(of: saveDestinations.isAnyDestinationEnabled"))
    }

    @Test("Auto-clear is exact-match scoped (== to constant, not hasPrefix or contains)")
    func contentViewAutoClearIsExactMatch() {
        // Anti-broadening guard: the .onChange body must compare lastError ==
        // DestinationGuardErrors.noDestinationsConfigured, NOT use hasPrefix or contains.
        // Allowing prefix/contains would mask unrelated errors that happen to share
```
