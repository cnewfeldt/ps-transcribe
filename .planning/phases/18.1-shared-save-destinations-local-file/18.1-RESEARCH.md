# Phase 18.1: Shared Save Destinations + Local File - Research

**Researched:** 2026-04-29
**Domain:** Swift/SwiftUI macOS app -- save-destination abstraction refactor
**Confidence:** HIGH (all findings are direct codebase observations or locked decisions from CONTEXT.md)

---

## Summary

Phase 18.1 refactors three divergent save paths (vaultMeetingsPath/vaultVoicePath for Obsidian, dictationFolderPath for dictation plain folder) into a single shared `SaveDestinations` fan-out layer. All content producers call one entry point; the layer routes to whichever destinations are enabled.

The codebase is in good shape for this refactor. `NotionService.buildProperties` already accepts a `sessionType: String` parameter and writes a `"Session Type"` Select property -- that plumbing is complete and requires only callsite updates. `DictationLogger` and `TranscriptLogger` are fully independent actors with clean interfaces. The biggest work is `DictationCoordinator.beginDictation` / `endDictation` (remove mode branches, wire `SaveDestinations`) and `SettingsView` (restructure Obsidian section, add Local File section, strip Dictation section of output-mode picker and folder picker).

**Primary recommendation:** Shape `SaveDestinations` as an `@Observable @MainActor final class` (matches the project's dominant service pattern). Instantiate at `PSTranscribeApp` scope; inject into `DictationCoordinator` and `ContentView`. Per-destination failures are non-fatal. Return a `SaveResult` struct with per-destination outcomes so the library entry caller picks a primary path.

### 1. Notion `session-type` property mechanism [VERIFIED: codebase]

**Finding:** `NotionService.buildProperties(...)` at `Notion/NotionService.swift:492-528` already includes a `"Session Type"` Select property:

```swift
"Session Type": [
    "select": ["name": sessionType]
],
```

The `sessionType: String` parameter is already wired through `sendTranscript(...)` (line 239) and `updateTranscript(...)` (line 139). The service uses schema-introspection: `sendTranscript` fetches `availableProps` from the database at call time and skips any property not present (lines 280-288). So if the user's Notion DB does not yet have a `"Session Type"` Select property, the property write is silently skipped -- no error thrown.

**Existing callers:** `ContentView.autoSendToNotion` (line 674) and `ContentView.sendToNotion` (line 709) pass hardcoded strings:
- `"Call Capture"` for `.callCapture`
- `"Voice Memo"` for `.voiceMemo`
- Dictation is never sent today (no existing callsite for `.dictation`)

**Recommendation:** No new property needed. The `"Session Type"` Select property already exists in `NotionService`. The values to pass are:
- `SessionType.callCapture` -> `"Meeting"` (rename from today's `"Call Capture"` to be consistent with CONTEXT D-03 values; or keep as-is for backward compat -- planner's call)
- `SessionType.voiceMemo` -> `"Voice Memo"` (already in use)
- `SessionType.dictation` -> `"Dictation"` (new)

The schema-introspection skip means: if the user does not have `"Session Type"` on their Notion DB, nothing breaks. If they do (likely, given the existing code has been writing it), the new `"Dictation"` value will appear as an unrecognized select option -- Notion creates it automatically on first write. No migration needed.

**Confidence:** HIGH -- direct code inspection.

### 2. `SaveDestinations` abstraction shape [VERIFIED: codebase patterns]

**Available shapes in the codebase:**
- `actor TranscriptLogger` -- I/O actor, called with `await`, no `@Observable`
- `actor DictationLogger` -- same pattern
- `actor NotionService` -- actor, pure API layer
- `@Observable @MainActor final class AppSettings` -- UI-bound state
- `@Observable @MainActor final class DictationCoordinator` -- app-scope service, owns state + side effects
- `@Observable @MainActor final class ModelUpdateService` -- external service wrapper

**Recommendation: `@Observable @MainActor final class SaveDestinations`**

Rationale:
1. It's the dominant pattern for app-scope services that own state visible to the UI (e.g., showing per-destination status in a future UI).
2. `DictationCoordinator` (already `@MainActor`) calls `endDictation()` from `@MainActor` context -- calling an `@MainActor` service is synchronous-feeling and avoids extra `await` hops.
3. `ContentView.startSession` is `@MainActor` -- same benefit.
4. Injected at app scope via `@State` in `PSTranscribeApp`, passed to `DictationCoordinator` and `ContentView` via initializer (same pattern as `libraryStore`, `sessionCoordinator`).

**Internal structure:** `SaveDestinations` holds concrete writer references:
- `private let localFileWriter: LocalFileWriter` (new actor -- I/O isolation)
- `private let obsidianWriter: ObsidianWriter` (new actor -- I/O isolation)
- `private let notionService: NotionService` (existing actor)
- reads `AppSettings` (injected, not held by reference -- or passed per-call)

**API:**
```swift
func save(content: String, metadata: SaveMetadata) async -> SaveResult
```
Where `SaveMetadata` carries `sessionType: SessionType`, `title: String`, `startDate: Date`, `duration: TimeInterval`, `sourceApp: String`, and `SaveResult` carries `localFileURL: URL?`, `obsidianFileURL: URL?`, `notionPageURL: URL?`, `inlineTranscript: String?`.

**Non-fatal failure:** Each destination is wrapped in `do { } catch { log.error(...) }`. Per-destination failure does not abort the others.

**Protocol-per-destination (`DestinationWriter`):** Possible but not necessary for three concrete cases with divergent write signatures. YAGNI. Can be extracted later when a fourth destination appears.

### 3. Writer factoring: reuse vs new [VERIFIED: codebase]

#### LocalFileWriter for Meeting/Memo

`TranscriptLogger.startSession(sourceApp:vaultPath:sessionType:...)` at line 102 accepts a `vaultPath: String` arg and creates the directory if absent (line 114). The `vaultPath` semantics are identical to `localFileRoot/Meeting` or `localFileRoot/Memo`. The full lifecycle (`startSession` -> `append` -> `endSession` -> `finalizeFrontmatter`) is already implemented.

**Recommendation:** `LocalFileWriter` for Meeting/Memo delegates to `TranscriptLogger`. The writer:
1. Resolves the subfolder path: `localFileRoot + "/" + sessionType.subfolder` (e.g., `Meeting/`)
2. Calls `transcriptLogger.startSession(sourceApp:vaultPath:subfolder:)` at session start
3. Existing `ContentView` session flow remains largely unchanged; it routes through `SaveDestinations` which routes to `LocalFileWriter` which routes to `TranscriptLogger`

**Alternative approach:** Since Local File for meetings IS the current behavior (just different path), it may be simpler to have `ContentView.startSession` continue calling `transcriptLogger.startSession` directly, just with the new path resolution. `SaveDestinations` then covers post-session notification sending and library-entry URL selection. The planner should weigh whether to fully route through `SaveDestinations` at session-start or only at session-end.

#### LocalFileWriter for Dictation

`DictationLogger` has a session-oriented API (`startSession(folderPath:)`, `append`, `endSession`, `discardSession`). Dictation in 18.1 is still session-streamed (Phase 18's `DictationCoordinator.beginDictation` -> `endDictation` lifecycle is preserved; only the mode-branch inside beginDictation is removed).

**Recommendation:** `LocalFileWriter` for dictation delegates to `DictationLogger`. The caller (`DictationCoordinator.beginDictation`) opens the session; `endDictation` closes it. `SaveDestinations` coordinates the session handoff:
- `beginDictation` calls `saveDestinations.beginDictationSession()` which calls `dictationLogger.startSession(folderPath: localFileRoot + "/Dictation")` if `localFileEnabled`
- `endDictation` calls `saveDestinations.endDictationSession(utterances:)` which calls `dictationLogger.endSession()` and fans out to Obsidian/Notion

The Obsidian write for dictation is a SINGLE POST-SESSION write (not session-streamed), because `ObsidianWriter` assembles the full content with frontmatter after the session ends. This matches how Notion works today.

#### ObsidianWriter: frontmatter reuse

`TranscriptLogger` contains frontmatter assembly scattered across `startSession` (writes initial frontmatter, lines 137-168) and `rewriteFrontmatter` (rewrites duration/attendees on finalization, lines 334-395). The frontmatter format is:

```
---
type: meeting | fleeting
created: "YYYY-MM-DD"
time: "HH:mm"
duration: "00:00"
source_app: "..."
source_file: "..."
attendees: []
context: ""
tags:
  - log/meeting | log/voice
  - status/inbox
  - source/meeting | source/voice
  - source/pstranscribe
---
```

**Recommendation:** `ObsidianWriter` is a new self-contained writer, NOT a delegate to `TranscriptLogger`. Rationale:
1. Obsidian writer needs a DIFFERENT frontmatter schema (must include `session-type:` per D-08; does not need `source_file:`, `context:`, `context` section in body).
2. Obsidian dictation writes never open a streaming file handle -- they write the complete file post-session.
3. `TranscriptLogger`'s frontmatter logic is entangled with its streaming append, diarization rewrite, and rename-on-context patterns -- extracting it would require major surgery.
4. The Obsidian frontmatter can be simpler and more uniform across all session types.

**Obsidian frontmatter schema:**
```yaml
---
session-type: meeting | memo | dictation
created: "YYYY-MM-DD"
time: "HH:mm"
duration: "MM:SS"
source_app: "..."
tags:
  - status/inbox
---
```

### 4. Library entry source-of-truth path resolution [VERIFIED: codebase]

**Current `LibraryEntry` shape** (`Models.swift` line 79):
```swift
struct LibraryEntry: Identifiable, Codable, Sendable {
    let id: UUID
    var name: String?
    let sessionType: SessionType
    let startDate: Date
    var duration: TimeInterval
    var filePath: String          // primary path (may be empty string for clipboard-only)
    let sourceApp: String
    var isFinalized: Bool
    var firstLinePreview: String?
    var notionPageURL: String?    // set after successful Notion send
    var inlineTranscript: String? // Phase 18 D-12: inline when no file written
}
```

`filePath` is a single `String`, not a typed URL field. `notionPageURL` is a separate field. There is no `obsidianFileURL` field today.

**18.1 requirement:** Row prefers Local File path > Obsidian path > Notion URL > inline transcript.

**Options:**

A. Add `obsidianFilePath: String?` alongside existing `filePath` and `notionPageURL`. `filePath` continues to be the primary path (Local File if written). After save, caller picks: set `filePath` to Local File URL, `obsidianFilePath` to Obsidian URL if written, `notionPageURL` to Notion URL.

B. Keep current `filePath` as the primary; `SaveDestinations.save()` returns `SaveResult` with all URLs; caller sets `filePath` = first non-nil of (localFileURL, obsidianFileURL, ""); sets `obsidianFilePath` if adding the field; sets `notionPageURL`.

**Recommendation (Option A + minimal addition):** Add `obsidianFilePath: String?` to `LibraryEntry`. Keep `filePath` as the primary display path (Local File when available, Obsidian otherwise, "" for Notion/inline). Add Codable backward-compat (`Optional` + missing key = nil, same pattern as `inlineTranscript`).

`SaveDestinations.save()` returns:
```swift
struct SaveResult {
    var localFileURL: URL?
    var obsidianFileURL: URL?
    var notionPageURL: URL?
}
```

Caller (DictationCoordinator.endDictation, ContentView session stop) sets:
- `filePath` = `localFileURL?.path ?? obsidianFileURL?.path ?? ""`
- `obsidianFilePath` = `obsidianFileURL?.path` (for future deep-link generation)
- `notionPageURL` = `notionPageURL?.absoluteString`
- `inlineTranscript` = transcript text if BOTH `localFileURL` and `obsidianFileURL` are nil and Notion-only

### 5. Filename collision for Obsidian (single folder, three content types) [VERIFIED: codebase]

**Today's schemes:**
- `DictationLogger` (line 52): `"yyyy-MM-dd HH-mm-ss-SSS Dictation.md"` (millisecond suffix, D-02)
- `TranscriptLogger.startSession` (line 134): `"yyyy-MM-dd HH-mm-ss [Voice Memo|Call Recording].md"` (no milliseconds)
- After rename via context/name: `"yyyy-MM-dd HH-mm-ss <name>.md"`

**Obsidian single-folder issue:** All three session types land in the same folder. Without type in the filename, `"2026-04-29 14-32-00 Some Name.md"` could be a meeting or a dictation.

**Recommendation:** Obsidian filenames always include the session type label immediately after the timestamp, before any auto-name:

```
2026-04-29 14-32-00-SSS Meeting <auto-name>.md
2026-04-29 14-32-00-SSS Memo <auto-name>.md
2026-04-29 14-32-00-SSS Dictation <auto-name>.md
```

Use millisecond suffix for all (collision-safety, consistent with DictationLogger). Trim `<auto-name>` to 40 chars (leaving room for prefix + suffix within 100-char total). If auto-name is empty/whitespace, omit it: `"2026-04-29 14-32-00-SSS Dictation.md"`.

**`obsidianVaultForPath` deep-link compatibility:** The function (`TranscriptParser.swift:79-97`) takes any file path and walks `~/Library/Application Support/obsidian/obsidian.json` vaults looking for a matching prefix. It does not inspect the filename at all -- only the folder prefix matters. Any filename format is compatible with deep-link generation as long as the file resides within a registered vault.

`makeObsidianURL` (`TranscriptParser.swift:105-130`) strips the vault root prefix to get a vault-relative path. Filename format does not affect this. No changes needed to these functions.

### 6. Vault detection in `Section("Obsidian")` [VERIFIED: codebase]

**`obsidianVaultForPath(path: String) -> (root: String, name: String)?`** is defined at `Storage/TranscriptParser.swift:79`. It reads `~/Library/Application Support/obsidian/obsidian.json`, extracts registered vault paths, and returns `(root, name)` if `filePath.hasPrefix(normalized + "/")`.

**Current two-folder detection** (SettingsView.swift lines 87-93):
```swift
private var detectedObsidianVault: (root: String, name: String)? {
    if !settings.vaultMeetingsPath.isEmpty,
       let v = obsidianVaultForPath(settings.vaultMeetingsPath) { return v }
    if !settings.vaultVoicePath.isEmpty,
       let v = obsidianVaultForPath(settings.vaultVoicePath) { return v }
    return nil
}
private var hasAnyObsidianFolder: Bool {
    !settings.vaultMeetingsPath.isEmpty || !settings.vaultVoicePath.isEmpty
}
```

**After 18.1 (single folder):**
```swift
private var detectedObsidianVault: (root: String, name: String)? {
    guard !settings.obsidianFolderPath.isEmpty else { return nil }
    return obsidianVaultForPath(settings.obsidianFolderPath)
}
private var hasObsidianFolder: Bool {
    !settings.obsidianFolderPath.isEmpty
}
```

**Status dot thresholds** (matching existing pattern):
- Gray (`.gray`) -- `!hasObsidianFolder` -- "Not configured"
- Green (`.green`) -- `hasObsidianFolder && detectedObsidianVault != nil` -- "Connected to vault: \(vault.name)"
- Orange (`.orange`) -- `hasObsidianFolder && detectedObsidianVault == nil` -- "Folder set, but not inside an Obsidian vault"

This is a direct port of the existing two-path logic to a single path. No changes to `obsidianVaultForPath` itself needed.

**Existing obsidianStatusText strings** (lines 139-146):
- `"Connected to vault: \(vault.name)"` -- keep verbatim
- `"Folder set, but not inside an Obsidian vault"` -- keep verbatim
- `"Not configured"` -- keep verbatim

### Pattern 1: SaveDestinations fan-out

```swift
// Source: codebase patterns (DictationCoordinator shape, ModelUpdateService shape)
@Observable
@MainActor
final class SaveDestinations {
    let settings: AppSettings
    let localFileWriter: LocalFileWriter
    let obsidianWriter: ObsidianWriter
    let notionService: NotionService

    func save(content: String, metadata: SaveMetadata) async -> SaveResult {
        var result = SaveResult()
        if settings.localFileEnabled {
            do {
                result.localFileURL = try await localFileWriter.write(
                    content: content, metadata: metadata)
            } catch {
                log.error("LocalFileWriter failed: \(error.localizedDescription, privacy: .public)")
            }
        }
        if settings.obsidianEnabled, !settings.obsidianFolderPath.isEmpty {
            do {
                result.obsidianFileURL = try await obsidianWriter.write(
                    content: content, metadata: metadata)
            } catch {
                log.error("ObsidianWriter failed: \(error.localizedDescription, privacy: .public)")
            }
        }
        if settings.notionAutoSendEnabled, !settings.notionDatabaseID.isEmpty {
            do {
                result.notionPageURL = try await notionService.sendTranscript(
                    databaseID: settings.notionDatabaseID, ...)
            } catch {
                log.error("NotionService failed: \(error.localizedDescription, privacy: .public)")
            }
        }
        return result
    }
}
```

### Pattern 2: ObsidianWriter frontmatter

```swift
// Source: phase decisions D-08, D-11; TranscriptLogger frontmatter as reference
actor ObsidianWriter {
    func write(content: String, metadata: SaveMetadata) async throws -> URL {
        let folderPath = metadata.obsidianFolderPath
        let directory = URL(fileURLWithPath: folderPath)
        try FileManager.default.createDirectory(at: directory, withIntermediateDirectories: true)

        let fileFmt = DateFormatter()
        fileFmt.dateFormat = "yyyy-MM-dd HH-mm-ss-SSS"
        let typeLabel = metadata.sessionType.obsidianLabel  // "Meeting" | "Memo" | "Dictation"
        let autoName = metadata.autoName.isEmpty ? "" : " \(metadata.autoName)"
        let filename = "\(fileFmt.string(from: metadata.startDate)) \(typeLabel)\(autoName).md"
        let fileURL = directory.appendingPathComponent(filename)

        let dateFmt = DateFormatter(); dateFmt.dateFormat = "yyyy-MM-dd"
        let timeFmt = DateFormatter(); timeFmt.dateFormat = "HH:mm"
        let durationStr = formattedDuration(metadata.duration)
        let sessionTypeValue = metadata.sessionType.frontmatterValue  // "meeting" | "memo" | "dictation"

        let fileContent = """
---
session-type: \(sessionTypeValue)
created: "\(dateFmt.string(from: metadata.startDate))"
time: "\(timeFmt.string(from: metadata.startDate))"
duration: "\(durationStr)"
source_app: "\(metadata.sourceApp)"
tags:
  - status/inbox
---

# \(typeLabel) -- \(dateFmt.string(from: metadata.startDate)) \(timeFmt.string(from: metadata.startDate))

\(content)
"""
        try fileContent.write(to: fileURL, atomically: true, encoding: .utf8)
        try FileManager.default.setAttributes(
            [.posixPermissions: NSNumber(value: 0o600)], ofItemAtPath: fileURL.path)
        return fileURL
    }
}
```

## Common Pitfalls

### Pitfall 1: Obsidian section restructure breaks deep-link generation for old files
**What goes wrong:** Library entries written before 18.1 have `filePath` pointing to `vaultMeetingsPath` or `vaultVoicePath`. After 18.1, `obsidianVaultForPath` is called with `settings.obsidianFolderPath`. Old files are in different folders.
**Why it happens:** We changed the folder used for vault detection, but library entries store absolute paths.
**How to avoid:** The library entry's stored `filePath` is an absolute path to the actual file. `obsidianVaultForPath(entry.filePath)` reads from `obsidian.json` -- it doesn't care which AppSettings key pointed to the folder. As long as the file exists on disk and the vault registration is unchanged, deep-links continue to work. No fix needed for existing entries.
**Warning signs:** Deep-link opens fail after 18.1 for old meeting entries -- but this would only happen if `obsidian.json` vault registration changed, not due to 18.1.

### Pitfall 2: Dictation session-start timing with SaveDestinations
**What goes wrong:** `DictationCoordinator.beginDictation` previously opened the `DictationLogger` session inline. If `SaveDestinations.beginDictationSession` is async and slow (e.g., directory creation on a cold path), it delays audio start.
**Why it happens:** Actor calls require `await`; directory creation is disk I/O.
**How to avoid:** `DictationLogger.startSession` already creates the directory synchronously within the actor. This was pre-existing; the overhead is minimal (< 1ms on normal disk). No change needed. Keep the `try?` fallback pattern (D-15 semantics: file-open failure is non-fatal for dictation).

### Pitfall 3: `DictationOutputMode` removed but old UserDefaults key persists
**What goes wrong:** After deleting the `dictationOutputMode` AppSettings property, the old `"dictationOutputMode"` value may still be in UserDefaults on development machines. This is harmless (D-17: no migration) but orphaned.
**Why it happens:** `UserDefaults.standard` is persistent.
**How to avoid:** Per D-17 this is acceptable. No cleanup code needed. Add `// No migration -- app not yet released to users` comment in AppSettings.init to document the intentional rip-and-replace.

### Pitfall 4: Clipboard write ordering -- clipboard before file writes
**What goes wrong:** If `SaveDestinations.save()` runs before the clipboard write, a slow Notion API call blocks the paste UX.
**Why it happens:** `await saveDestinations.save(...)` is async and may wait on Notion HTTP.
**How to avoid:** In `DictationCoordinator.endDictation`, ALWAYS call `writeToClipboardWithPrivacyMarkers` and `scheduleClipboardRestore` FIRST (D-15), then call `await saveDestinations.saveDictation(...)`. This is already the existing order in Phase 18; preserve it.

### Pitfall 5: SettingsView source-grep tests reference deleted properties
**What goes wrong:** `SettingsViewDictationSectionTests` (line 34) greps for `"$settings.dictationOutputMode"` -- after 18.1 this property is deleted and the grep fails.
**Why it happens:** The tests verify the source text of SettingsView.
**How to avoid:** DELETE `dictationOutputMode` grep test; ADD equivalent tests for new properties (`$settings.localFileEnabled`, `$settings.obsidianFolderPath`, etc.). See Validation Architecture section.

### Pitfall 6: NotionService `"Session Type"` value casing inconsistency
**What goes wrong:** Existing calls pass `"Call Capture"` for meetings (ContentView line 674). 18.1 should unify to `"Meeting"` but changing this renames the Notion select option, potentially creating a duplicate.
**Why it happens:** Notion Select properties store the option string as the canonical value; changing the string creates a new option.
**How to avoid:** The planner must decide: (a) keep `"Call Capture"` for `.callCapture` to avoid Notion side effects, or (b) migrate to `"Meeting"` and accept the new option appearing. Since the app is not yet released (D-17 scope), option (b) is safe. Recommend using consistent `"Meeting"` / `"Voice Memo"` / `"Dictation"` for all three.

### Pitfall 7: Local File writer session lifecycle for meetings
**What goes wrong:** `TranscriptLogger` is a session-streaming actor -- it opens a file at session START, appends utterances during recording, and finalizes at session END. `SaveDestinations` cannot replace `TranscriptLogger` as a post-session one-shot writer for meetings.
**Why it happens:** Meetings are hours-long; transcript must be written incrementally to survive crashes (STAB-03 checkpoint pattern).
**How to avoid:** For meetings, `ContentView.startSession` must continue to open `TranscriptLogger` at session start (routing the `vaultPath` arg to `localFileRoot + "/" + sessionType.subfolder`). `SaveDestinations` is involved at session-end for Notion + Obsidian (one-shot post-session writes). The Local File path for meetings is effectively "handled by the existing `TranscriptLogger` session, just with a new path."

private func validatedFolderPath(_ rawPath: String) throws -> URL {
    let expanded = NSString(string: rawPath).expandingTildeInPath
    guard !expanded.isEmpty,
          !expanded.contains("\0"),
          !expanded.contains("..") else {
        throw DictationLoggerError.folderPathInvalid(rawPath)
    }
    return URL(fileURLWithPath: expanded).resolvingSymlinksInPath().standardized
}

## Open Questions

1. **Should `ContentView.startSession` be routed through `SaveDestinations` at session-start for Local File, or does it continue calling `TranscriptLogger.startSession` directly?**
   - What we know: `TranscriptLogger` is session-streaming; it must be opened at session-start, not at session-end.
   - What's unclear: Whether `SaveDestinations` should wrap this session-start call or whether it only handles post-session fan-out.
   - Recommendation: For meetings, `ContentView.startSession` continues calling `transcriptLogger.startSession(vaultPath: settings.localFileRoot + "/" + sessionType.subfolder)` directly. `SaveDestinations` handles post-session Obsidian and Notion writes. `LocalFileWriter` is used only for dictation (where the write is session-oriented but can be driven by `DictationCoordinator`). This avoids making `SaveDestinations` a complex lifecycle manager.

2. **Does `obsidianFilePath` need to be added to `LibraryEntry` now, or can the Obsidian deep-link work from `filePath` when Obsidian is the primary path?**
   - What we know: `obsidianVaultForPath(entry.filePath)` already works for any absolute path. If `filePath` is set to the Obsidian file path (when Obsidian is the primary and Local File is disabled), deep-links work without an additional field.
   - What's unclear: Whether the planner wants an explicit `obsidianFilePath` for UI purposes (e.g., showing "Open in Obsidian" button independent of `filePath`).
   - Recommendation: Defer adding `obsidianFilePath` unless UI explicitly requires it. Use `filePath` priority ordering (Local File > Obsidian path) and let `obsidianVaultForPath(entry.filePath)` detect vault membership.
