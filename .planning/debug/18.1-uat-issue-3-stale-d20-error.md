## Resolution

root_cause: |
  The D-20 guard in `ContentView.startSession` (PSTranscribe/Sources/PSTranscribe/Views/ContentView.swift:826–830) sets `transcriptionEngine.lastError` to a non-nil string and returns early. The two start buttons in CaptureDock (capturePrimaryButton lines 143–180, voiceMemoButton lines 182–215) gate their click handlers on `!hasError` (CaptureDock.swift:147, 184), where `hasError == lastError != nil` (TranscriptionEngine.swift:46 + 40). No code path in the project clears `transcriptionEngine.lastError` in response to a destination toggle: there is no `.onChange(of: settings.localFileEnabled)` (or sibling) handler, no didSet on the `@Observable` settings, and no observer in `SaveDestinations` that fires on `isAnyDestinationEnabled` flipping false→true. The result is a one-way trap: D-20 sets the error, the buttons silently no-op, and no UI action other than relaunching the app can reach a `lastError = nil` site.

fix: |
  Add a settings-driven auto-clear so that when the user re-enables a destination, the D-20 lastError is dismissed. The cleanest place is ContentView's body modifier stack — alongside the existing `.onChange(of:)` calls — observing `saveDestinations.isAnyDestinationEnabled` and clearing `transcriptionEngine.lastError` only if it currently equals the D-20 message (so we don't accidentally swallow unrelated errors like mic-permission or save-failure messages).

  Suggested location: PSTranscribe/Sources/PSTranscribe/Views/ContentView.swift, in the same block as the existing `.onChange(of: settings.inputDeviceID)` (line 432).

  Suggested snippet (add as a sibling .onChange):

      // 18.1 D-20 recovery: when the user enables a destination after the
      // "no destinations" guard fired, clear the inline error so the start
      // buttons re-engage. Scoped to the D-20 message so we don't suppress
      // unrelated errors (mic permission, save failures).
      .onChange(of: saveDestinations.isAnyDestinationEnabled) { _, isEnabled in
          guard isEnabled,
                let err = transcriptionEngine?.lastError,
                err.hasPrefix("No save destination configured")
          else { return }
          transcriptionEngine?.lastError = nil
      }

  Notes:
  - Match-by-prefix on the D-20 string is intentional: the guard message in startSession (line 827) is the only producer of that prefix, so this is precise.
  - An alternative is to extract the D-20 message to a single constant on `SaveDestinations` (or a new `D20Errors` namespace) and compare against that constant — slightly safer than a string-prefix check. Recommend this for the actual fix to avoid string-drift between guard and clear.
  - Do NOT change the button-disable predicate to "lastError nil OR isAnyDestinationEnabled" — that would let the user click through other legitimate errors. Targeted clear is the correct discipline.
